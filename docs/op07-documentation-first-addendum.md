## Regression contract

- Generic historical control absence plus positive domains activates compatible controls; expansion/contraction follows current domains.
- Explicit current UNKNOWN/UNSUPPORTED/CONFLICT, malformed domains and untyped provider options do not silently activate.
- Recovered values pass the real validator and serializer, with normalized wire fields and correct geometry omission.
- Documented reference count ranges, combinations, media budgets and provider passthrough retain source/transport restrictions.
- Existing links, saved model IDs and workflow intent remain preserved. Classic and Nodes 2.0 share the same Core projection; offline checks are not live Owner acceptance.
- Paid submit remains at most one POST; Resume, polling and failure do not authorize another submit. No authentication, attribution, network, storage or dependency policy changes.

The supplied audit_all_models.py remains an offline operator tool using the existing Core. It compares identical captured snapshots; synthetic registry fixtures are labeled separately from the public live catalogue. The TEST bundle may carry this tool for future checks; it is not installed as a runtime engine and does not scrape docs, mutate capabilities or install code.

No TEST/DEV/PROD/RC, account, ACL, vault, user workflow, frozen RC.2, paid operation, OAuth, S3, merge, tag or publication is changed by this offline integration. A new immutable candidate must pass the project regression, static and Contract Guard checks and a scoped independent review before TEST installation is separately authorized.

A further reproducible pre-existing regression was exposed by the repository's future structured-model test: explicit mixed-reference support disappeared merely because no numeric ceiling was published. The canonical derived recipe now retains that positive operation as DOCUMENTED_CONTRACT. Unknown cardinality remains visibly unpublished (not COMPLETE, not an unlimited guarantee); known type/combination/minimum/explicit ceilings still validate. Historical successful examples are evidence, not an exclusive whitelist. Explicit unknown wire contracts, current unknown recipes, malformed constraints and conflicts remain blocked. A separate zero/small per-kind contradiction check prevents false READY for impossible shapes.
